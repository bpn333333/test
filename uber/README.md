# 配達1件ごとの記録から、効率よく稼ぐ動き方を出す

`drivers.uber.com/earnings/activities` の**アクティビティを1件ずつ**集め、
そこから「明日からどう動くか」を決めるための道具。

出すのは指標ではなく**行動**。次の4つに答える。

1. **受注判断** — どの条件の注文を断ると時給が上がるか（閾値を総当たりで検証）
2. **稼働枠** — 何曜日の何時に走るか、どこを削るか
3. **待機場所** — 配達後どのエリアに戻るか
4. **受取先** — 待たされて損をしている店はどこか

---

## 1. 集める（ここが全て）

**分析の精度は、1件あたり何を取れたかで決まる。** 金額と日時だけでは
「いつ走るか」しか出ない。断るべき注文も、避けるべき店も分からない。

### 取ってほしい項目

| 項目 | 無いとどうなるか |
|---|---|
| **日時** | 必須 |
| **報酬** | 必須 |
| **所要時間** | **受注判断が丸ごと出せない**（最重要） |
| **距離** | 「何km以上を断るか」が出せない |
| **受取場所（店名）** | 避けるべき店が特定できない |
| **配達先エリア** | 待機場所が決まらない |
| 店での待ち時間 | あれば店ごとの損失が正確になる |
| チップ / プロモ内訳 | あれば基本報酬だけの実力が分かる |

上4つが揃えば主要な判断は全部出る。**所要時間だけは必ず取ること。**

### 取り方

このリモート環境からは `drivers.uber.com` に到達できない（ネットワークポリシーで
CONNECT が拒否され、加えてログインに SMS 認証が必要）。**下のどちらかで集める。**

#### ルートA — Claude in Chrome（推奨・即日）

本人のログイン済みブラウザで動くので、活動画面をそのまま読める。
明細を1件ずつ開く必要があるため、まず**直近3〜4週間分**で始めるのが現実的。

Chrome 側にそのまま渡す指示:

```
drivers.uber.com/earnings/activities を開いてください。

1. ページ下端まで繰り返しスクロールし、対象期間の配達をすべて読み込む
2. 配達を1件ずつ開き、明細から次の項目を読み取る
3. 全件を1つのCSVにまとめて出力する

日時,報酬,所要時間,距離,受取場所,配達先エリア,待ち時間

- 日時は YYYY/MM/DD HH:MM
- 報酬・距離・時間は数字のみ（¥ , km 分 は不要）
- 受取場所は店名、配達先エリアは市区町村まで
- 読み取れない項目は空欄のままにする（推測で埋めない）
- 途中で件数を報告し、取りこぼしがないか確認しながら進める
```

#### ルートB — 公式データ書き出し（全期間・数日かかる）

`drivers.uber.com` → アカウント/設定 → プライバシー → **データのダウンロード**を申請。
数時間〜数日でリンクがメールで届く。全期間が漏れなく入るのが利点。
ただし**明細の粒度は書き出しの仕様次第**で、店名やエリアが含まれないことがある。

→ **まずルートAで直近分を取り、並行してルートBを申請しておく**のが最短。

CSV は `uber/data/` に置く（`.gitignore` 済み。収入明細はコミットされない）。

## 2. 分析する

```bash
python3 uber/analyze.py uber/data/*.csv
```

標準ライブラリのみで動く。文字コード（UTF-8 / Shift_JIS）、区切り文字、
列名（日本語・英語）は自動判定する。列名が違っても動くよう総当たりで当てるので、
**手で整形し直す必要はない。**

```bash
# 書き出しがUTCだったとき（深夜帯が多すぎると自動で警告が出る）
python3 uber/analyze.py uber/data/*.csv --tz-shift 9

# 稼働の区切り判定を変える（既定: 45分以上空いたら別セッション）
python3 uber/analyze.py uber/data/*.csv --gap-min 60
```

## 3. 出力の読み方

### 「受注判断」の2つの数字

断ったあとの時間をどう見るかで結果が変わるため、上下2つを併記している。

- **働いた分の単価** = 受けた注文の報酬 ÷ 所要時間
  空き時間が同水準の注文で埋まる前提。**上限**
- **実効時給** = 受けた注文の報酬 ÷ 総オンライン時間
  空き時間が一切埋まらない前提。**下限**

**この2つの差が小さいルールほど安全**に実行できる。
差が大きいルールは「注文が途切れない時間帯でだけ」使う。
暇な時間帯で選り好みすると、断って空いた時間の損が上回る。

### 効果の測り方

**一度に全部変えないこと。** まず受注ルールだけを2週間試し、同じ手順で
データを取り直して実効時給が上がったかを見る。上がってから次の1つを足す。
同時に3つ変えると、何が効いたのか分からなくなる。

---

## 注意

- **2〜3ヶ月分を通して見ること。** 天候・季節・キャンペーンで大きく振れるので、
  直近2週間だけで受注ルールを決めると外す
- **プロモ込みの数字で判断しない。** クエストやブーストは Uber 側の裁量で縮む。
  内訳が取れているなら、基本報酬だけの時給も併せて確認する
- **エリアや店の評価は件数を見る。** 3〜5件の実績で「この店は避ける」と
  決めるのは早い。件数が積み上がってから固定する
