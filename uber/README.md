# Uber 稼働データの収集と分析

`drivers.uber.com/earnings/activities` の全取引を集め、**PLAN.md の3つの意思決定**に
決着をつけるための道具一式。

---

## 0. なぜ集めるのか（集める前に確認する）

データを眺めるためではなく、次の3つを**数字で確定させる**ためだけに集める。
これ以外の分析はしない。

| 決定 | いま何になっているか | データで何が変わるか |
|---|---|---|
| **A. 案件の足切りライン** | Uber = ¥2,000/h と**保守的に仮置き**。実績は2,500〜3,000という体感 | 実効時給の実測値。¥3,000 の見送りラインを維持するか動かすかが決まる |
| **B. 9/10 中間チェックでの「Uber 増枠」** | 「4〜5h/日 → 24〜30万」と**時給一定を仮定**した試算 | 曜日×時間帯別の実測時給。**足すべき枠と、足しても割に合わない枠**が分かれる |
| **C. 11月の谷（▲55万）を Uber でどこまで埋められるか** | 「8h/日×週5 = 32万」 | 上限の現実性。ピーク帯が1日3〜5時間しかなければ32万は届かない |

> **Bが最重要。** PLAN.md の増枠試算は「8時間ずっと同じ時給で走れる」前提で組んである。
> 実際にはピーク帯（昼・夕食時）以外は単価が落ちるため、稼働時間を2倍にしても
> 収入は2倍にならない。ここを実測で置き直さないと、11月の資金計画が楽観側にぶれる。

## 1. 収集する（本人の手が1回だけ必要）

このリモート環境からは `drivers.uber.com` に到達できない（ネットワークポリシーが
CONNECT を 403 で拒否。加えてログインに SMS 認証が要る）。HANDOFF.md 第9章と同じ制約。
**下のどちらかで CSV を取得し、`uber/data/` に置く。**

### ルートA — Uber の公式データ書き出し（推奨・全期間が確実に入る)

1. `drivers.uber.com` にログイン
2. アカウント／設定の中の **プライバシー** から **データのダウンロード** を申請
   （表記は「データをダウンロード」「個人データのリクエスト」など時期により異なる）
3. 数時間〜数日で**ダウンロードリンクがメールで届く**
4. zip を展開し、中の CSV を `uber/data/` に置く

- 全期間の取引が漏れなく入るのが利点。画面のスクロールでは取りこぼす古い期間も入る
- **オンライン時間のファイルが同梱されていたら必ず一緒に置く。**
  実効時給が「推定」から「実測」に変わり、決定Aの精度が段違いになる
- 時刻が **UTC** で書き出されることがある。その場合は `--tz-shift 9` を付ける
  （深夜帯の取引が不自然に多ければUTC。ツールが自動で警告する）

### ルートB — Claude in Chrome で活動画面から収集（即日ほしいとき）

申請の待ち時間を挟めないときはこちら。Chrome 側に渡す指示:

```
drivers.uber.com/earnings/activities を開き、ページ下端まで繰り返しスクロールして
すべての取引を読み込んでから、全行を以下の列のCSVで出力してください。
取りこぼしを防ぐため「これ以上読み込まれない」ことを確認してから出力すること。

日時,取引タイプ,金額

- 日時は YYYY/MM/DD HH:MM 形式
- 金額は数字のみ（¥ とカンマは不要）
- 取引タイプは画面の表記のまま（配達 / チップ / クエスト など）
```

- 画面が保持している期間しか取れない（数週間〜数ヶ月）点に注意
- オンライン時間は取れないので、実効時給は**推定**になる

### 取れなかったとき

`analyze.py` は列名を総当たりで検出するが、未知の書式なら
`0. 読み込み` に検出できた列名が出る。手で整形するなら最低限
**日時と金額の2列**があればよい。種別列があると内訳（チップ／クエスト）も出る。

## 2. 分析する

```bash
# 基本
python3 uber/analyze.py uber/data/*.csv

# オンライン時間の実測があるとき（実効時給が推定でなく実測になる）
python3 uber/analyze.py uber/data/payments.csv --hours uber/data/online.csv

# 書き出しがUTCのとき
python3 uber/analyze.py uber/data/*.csv --tz-shift 9

# 11月に必要な額でシミュレーション
python3 uber/analyze.py uber/data/*.csv --target 320000
```

標準ライブラリのみで動く（pandas 不要）。文字コード（UTF-8 / Shift_JIS）と
区切り文字は自動判定する。

### 出力されるもの

| 節 | 内容 | 対応する決定 |
|---|---|---|
| 0 | 読み込み結果と列マッピング | — |
| 1 | 種別内訳・**インセンティブ依存度**・月別推移 | C |
| 2 | **実効時給** と PLAN.md 基準線(¥2,000)の検証 | **A** |
| 3 | 曜日×時間帯ヒートマップ・時間帯別単価・**増枠候補** | **B** |
| 4 | 目標金額に対する必要稼働時間 | **C** |

## 3. 数字が出たら

`uber/STRATEGY.md` の判断表にそのまま当てはめる。閾値と、閾値を跨いだときに
PLAN.md のどこを書き換えるかまで決めてある。
