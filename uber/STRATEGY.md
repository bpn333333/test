# Uber データの読み方と判断ルール

`analyze.py` の出力を、そのまま行動に変換するための表。
数字が出る前に閾値を決めておくのは、**数字を見てから基準を動かさないため**。

---

## 決定A — 案件の足切りラインは正しいか

PLAN.md 第1関門は `Uber ¥2,000/h` を基準線に置き、その1.5倍の **¥3,000未満は見送り**
としている。実測値をここに当てる。

| 実効時給の実測 | 判断 | PLAN.md をどう書き換えるか |
|---|---|---|
| **¥2,000 未満** | 基準線が楽観だった | 足切りを実測×1.5に**引き下げる**。いま見送っている案件帯が実は有利になる |
| **¥2,000〜2,600** | 保守見積は妥当 | **変更なし。** ¥3,000 の足切りを維持 |
| **¥2,600〜3,200** | 実測が保守見積を上回る | 足切りを **¥3,900〜4,800 に引き上げ**。いまの ¥3,000 は Uber に負ける水準 |
| **¥3,200 超** | 時間拘束契約の多くが Uber に劣る | 第3層（SOKUDAN / Workship の20〜40万帯）は**原則見送り**に格下げ。第1層と第2層に集中 |

**注意: 推定値と実測値を区別すること。**
オンライン時間のファイルがない場合、実効時給は取引間隔からの**推定**であり、
待機時間を取りこぼして**高めに出る**。推定値で足切りを引き上げてはいけない。
引き上げるなら実測のオンライン時間を取ってから。

## 決定B — 増枠するならどの枠か（9/10 中間チェックで使う）

PLAN.md の「4〜5h/日 → 24〜30万 / 8h/日×週5 → 32万」は、**時給が一日中一定という仮定**で
組まれている。これが最大の穴。

出力3節の「時間帯別の1件単価」を見て、次の順で決める。

### 手順1 — 足す前に、置き換える

現行枠は平日 18-21時 / 水曜 19-22時 / 週末 18-21時。
**「増枠候補」に出た時間帯の単価が、現行枠の最低単価を上回っているなら、
時間を増やす前にそこへ移す。** 総稼働を変えずに収入が上がる。

### 手順2 — 限界時給で足す

追加する1時間の価値は、平均時給ではなく**その時間帯の実測時給**で測る。

| 追加候補枠の実測単価 | 判断 |
|---|---|
| 現行枠の平均以上 | 迷わず足す |
| 平均の70〜100% | 案件獲得の時間（10-13 / 14-17）を潰さない範囲でのみ足す |
| 平均の70%未満 | **足さない。** その時間は案件獲得か Kindle に使う方が期待値が高い |

### 手順3 — 水曜を検算する

水曜は HashPort 終日出社の後に 19-22時。疲労コストが最も高い枠。
曜日別の「1日平均」で水曜が下位なら、**9月中は水曜のデリバリーを外して
事務・休息に充てる**方が、翌日の稼働品質を通じて週合計では勝つ可能性がある。
データで水曜が上位なら維持。

## 決定C — 11月の谷を Uber でどこまで埋められるか

### 前提の算数（PLAN.md 第2章より）

```
11月:  Uber 15万 + 新規案件の初回入金(11/30着金) − 支出 70万 = ▲55万
```

Uber を最大まで伸ばしても（PLAN.md の試算で週6×8h ≈ 38万）、現行15万に対して
**+23万**。▲55万は**埋まらない**。

> **Uber 増枠は谷を消す手段ではなく、谷を浅くする1本の板。**
> PLAN.md 第3章の保険6本を全部立てる前提は変わらない。データで変わるのは
> 「この板が何万円分の厚みを持つか」だけ。

### データで確定させること

出力4節の「必要稼働時間」を見る。ただし**この数字は平均時給での割り算なので楽観側**。
正しくは3節の時間帯別データで置き直す:

```
現実的な上限 = (ピーク帯の時間数 × ピーク帯の時給) + (それ以外の時間数 × 非ピーク時給)
```

ピーク帯が1日3〜5時間しかないなら、8時間走っても後半3時間は非ピーク時給になる。
**この差が PLAN.md の32万との乖離**であり、11月の資金計画が楽観にぶれる原因。

### 上限を決めるのは Uber ではなく案件側

11月は新規案件が稼働している。増枠の天井は「Uber に走れる時間があるか」ではなく
**「案件の稼働日数を削らずに空いている時間はどれだけか」**で決まる。
週5の案件が入っていれば、増枠できるのは平日夜と週末だけ。
→ **増枠の試算は必ず「契約後の空き枠」に対して行う。空き枠を無視した最大値を
資金計画に載せない。**

## この分析から結論してはいけないこと

- **「時給が高いから Uber を増やす」** — 時給の上限が固定でキャリアに積み上がらない点は
  データが何を示しても変わらない。PLAN.md の「橋であって恒久策にはしない」は維持
- **インセンティブを恒久収入として計上する** — クエスト・ブーストは Uber 側の裁量で
  縮む。依存度が25%を超えていたら、資金計画は**インセンティブを除いた額**で組む
- **直近数週間だけを見て判断する** — 天候・季節・キャンペーンで大きく振れる。
  最低でも2〜3ヶ月分を通して見る（ルートAの公式書き出しを推奨する理由）
- **推定時給で足切りラインを引き上げる** — 決定Aの注意書きを参照
