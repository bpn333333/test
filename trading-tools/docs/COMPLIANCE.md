# 商品化・配信の前に確認すること

**これは法的助言ではない。** 該当しうる論点を洗い出したチェックリストであり、
実際の可否は必ず弁護士または金融庁・財務局の相談窓口で確認すること。
金額の大きい話ではなく、無登録営業は刑事罰の対象になりうるという性質の話。

## 1. 金融商品取引法 — 投資助言・代理業の登録

店頭FXは金商法上のデリバティブ取引にあたる。その売買判断について
**「報酬を得て」「助言する契約に基づき」助言する**と、投資助言・代理業の
登録が必要になる。無登録での営業は刑事罰の対象。

判断が分かれやすい境界を、リスクの高い順に並べる:

| 形態 | リスク |
|---|---|
| 有料会員に個別のエントリー/決済タイミングを配信 | **高い。** 典型的な投資助言 |
| ツール本体を有料販売し、購入者にシグナルも配信する | **高い。** 販売とセットだと助言性が出る |
| ツール(プログラム)だけを有料販売し、判断は購入者が行う | **要確認。** 一般に助言そのものではないと整理されることが多いが、宣伝の仕方次第で助言と評価されうる |
| 無償で不特定多数に公開する | 相対的に低い。ただし「無償」の実態が伴うこと |

**判断すべきこと(先送りしない):**

- [ ] 何を有償にするのか。ツールか、シグナルか、教育コンテンツか
- [ ] 有償シグナル配信をやるなら、登録を取るか、やらないか
- [ ] 登録しないと決めたなら、その線引きを文書で持ち、運用でも守る

## 2. 表現の規制

登録の有無にかかわらず、**書き方そのものが違反になりうる**。

- 断定的判断の提供(「必ず上がる」「絶対に勝てる」)は禁止行為
- 「勝率100%」「元本保証」「損しません」は使わない
- 実績を出すなら、検証可能な記録が要る(景品表示法の優良誤認)
- 打消し表示(小さい免責)で誇大表現を打ち消すのは認められにくい

`distribution/tradetools_x/composer.py` の `PROHIBITED_PATTERNS` が
これらを機械的に弾く。**フィルタを緩めるときは、なぜ緩めるかを記録すること。**

## 3. 実績を出すなら記録が要る

「バックテストで年利◯%」を出すなら、少なくとも以下を保存しておく。

- [ ] 使用したヒストリカルデータの出所と期間、ブローカー名
- [ ] スプレッド・スワップ・手数料の前提
- [ ] EAのバージョンとパラメータ(コミットハッシュで特定できる状態)
- [ ] バックテストレポートの原本(HTML/画像)
- [ ] フォワード(実口座またはデモ)の記録

**バックテストの成績を実績として売り文句にするのは、フォワードが揃うまで避ける。**
過去データへの最適化(カーブフィッティング)は必ず起きるため。

## 4. 特定商取引法

有料販売するなら、販売ページに事業者名・所在地・連絡先・価格・
支払方法・引渡時期・返品条件の表示が必要。合同会社櫻源郷の情報を使う。

- [ ] 特商法表記ページを用意する
- [ ] 返金ポリシーを決める(「一切返金不可」は消費者契約法上の論点になりうる)

## 5. プラットフォーム側の規約

- X の自動化ポリシー: 同一・類似内容の連投、過剰投稿は制限対象。
  `PublisherConfig` の `max_posts_per_day` と `min_interval_seconds` は
  控えめに設定してある。緩めないこと
- MQL5 マーケットで売る場合は MetaQuotes の審査基準が別途ある
- FX業者によっては自動売買・EAの利用条件が異なる。**口座を作る前に確認する**

## 6. 配信に必ず入れる文言

`composer.DEFAULT_DISCLAIMER` が既定で入れているもの:

> ※投資助言ではありません。売買の最終判断はご自身の責任でお願いします。

販売・配信の規模を広げるなら、これに加えて以下をランディングページ側に置く。

- 過去の成績は将来の結果を保証しないこと
- 損失が生じる可能性、レバレッジ取引のリスク
- 提供するのはツールであって、投資勧誘ではないこと

## 着手前に決める3点

1. 有償にするのはツールか、シグナルか(ここで登録の要否が変わる)
2. 実績表示をするか、しないか(するなら記録の仕組みを先に作る)
3. 配信は無料公開か、会員限定か
