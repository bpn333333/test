# 設計 — 4つのツールをどう1本につなぐか

## 全体像

```
        ┌─────────────────────────────────────────────┐
        │  SignalCore.mqh  ← 判定ロジックはここだけ    │
        └───────┬──────────────────────┬──────────────┘
                │                      │
      ┌─────────▼─────────┐  ┌─────────▼─────────┐
      │ ① サインツール     │  │ ② EA              │
      │ 矢印 + アラート    │  │ 発注・決済・保護   │
      └─────────┬─────────┘  └─────────┬─────────┘
                │                      │
                └──────┬───────────────┘
                       │  signals.csv(追記専用)
             ┌─────────▼──────────┐
             │ ③ 市場モニタリング  │  通知: コンソール / ファイル / Webhook
             │  (Python)          │
             └─────────┬──────────┘
                       │  Signal オブジェクト
             ┌─────────▼──────────┐
             │ ④ X配信            │  免責付与 → 禁止表現検査 → 重複排除 → 投稿
             │  (Python)          │
             └────────────────────┘
```

## 一番大事な設計判断: 判定ロジックを二重に持たない

4つのツールがそれぞれ独自に「買いだ/売りだ」を判断すると、
**チャートの矢印とEAの発注とXの投稿が食い違う。** 商品として最悪の事故になる。

そこで判定は `mt5/Include/TradeTools/SignalCore.mqh` の1箇所だけに置き、
インジケータもEAもそこを呼ぶ。Python 側の
`monitor/tradetools_monitor/signals.py` はその鏡像で、
**両者が一致することを `tests/test_parity.py` で機械的に検証する。**

ロジックを変更するときの手順:

1. `SignalCore.mqh` を変更
2. `signals.py` を同じ内容に変更
3. MT5 で `TradeToolsExport.mq5` を実行して CSV を書き出す
4. `pytest tests/test_parity.py` が通ることを確認
5. どちらか片方だけ変更した状態でコミットしない

## リペイントさせない

サインツールが後から矢印を消す(リペイント)と、配信の信頼が一発で消える。

- 判定は必ず**確定足**(`shift=1` 以降)で行う。未確定足では判定しない
- インジケータの通知は「新しい足が始まった瞬間」に1回だけ
- EAも同じタイミングでしか発注しない

## 判定ロジック(初期版)

トレンドフォローの素直な型。**これは叩き台であって、優位性の検証はこれから。**

| 段階 | 内容 |
|---|---|
| 時間帯 | サーバー時間 8〜22時。週末と金曜20時以降は新規なし |
| トレンド | 終値が EMA200 の上(買い)/下(売り) |
| モメンタム | ADX ≧ 20。下回ればレンジとみなして見送り |
| 発生 | EMA12 が EMA48 を上抜け(買い)/下抜け(売り) |
| 損切り | ATR × 1.5 |
| 利確 | 損切り幅 × 1.8(リスクリワード 1.8) |

## EA が持つ保護

判定と発注は責務を分けてある。EA 側の `RiskManager.mqh` は口座を守る係。

- ロットは「損切りまでの距離」から逆算し、1トレードの損失を残高の1%に固定
- 同時保有数の上限
- 当日損失が残高の3%に達したらその日は新規停止
- スプレッド上限を超えたら発注しない
- ブローカーの最小ストップ距離を満たさない注文は出さない
- 建値移動 + ATRトレーリング + 逆シグナル決済

## MT5 と Python の受け渡し

共有フォルダの追記専用CSV(`MQL5/Files/TradeTools/signals.csv`)1本だけ。

- MQL5 が書き、Python は読むだけ。逆流させない
- 書き込み途中の行に当たることがあるため、Python 側は壊れた行を捨てて次回読み直す
- `signal_id`(銘柄-時間軸-足の時刻-方向)が重複排除のキー。同じ足で二度配信しない

MT5 が動く PC と配信サーバを分ける場合は、この CSV を同期するだけでよい。

## 配信の安全装置

X配信は「間違った文面を世界に出す」事故が一番怖いので、多段で止める。

1. `composer` が免責文を必ず付ける。無ければ例外で停止
2. 断定表現(「必ず儲かる」「元本保証」等)を検出したら停止
3. X の重み付け文字数(日本語1文字=2)で上限超過を検出
4. `publisher` が重複・投稿間隔・1日上限を管理(再起動しても効く)
5. 既定は**ドライラン**。`--live` を明示するまで実際には投稿しない
