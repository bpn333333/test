# rdcontrol — ローカルデスクトップのリモート操作アプリ

自分の PC でサーバーを起動すると、別の端末のブラウザからその PC の画面を見て、
マウスとキーボードで操作できます。追加のクライアントアプリは不要で、
接続側はブラウザだけあれば動きます。

```
[操作する端末のブラウザ]  ──WebSocket──▶  [rdcontrol サーバー]  ──▶ 自分のデスクトップ
        画面(JPEG)      ◀──────────────      画面キャプチャ / 入力再生
```

## できること

- デスクトップ画面のライブ表示(変化があったときだけ送るので、静止中は帯域をほとんど使わない)
- マウス移動 / 左右中クリック / ドラッグ / ホイールスクロール
- キーボード入力(修飾キーは左右を区別、F1〜F20、Ctrl+C などの組み合わせも可)
- マルチモニタの切り替え、画質・フレームレート・解像度の調整
- 閲覧専用モード(`--view-only`)、同時接続数の上限、操作権は常に 1 人だけ

## 動作要件

- Python 3.10 以上
- **デスクトップにログイン済みのセッション**で実行すること(SSH のみの接続やヘッドレス環境では画面を取得できません)
- OS ごとの追加設定:
  - **macOS**: 「システム設定 → プライバシーとセキュリティ」で、実行するターミナル(または Python)に
    **画面収録**(キャプチャ用)と**アクセシビリティ**(入力操作用)の許可が必要です。
  - **Windows**: 追加設定は不要です。ただし管理者権限で動くウィンドウ(UAC のダイアログなど)は、
    同じく管理者権限で起動しないと操作できません。
  - **Linux**: X11 が必要です(`DISPLAY` が設定されていること)。Wayland では
    画面キャプチャ・入力合成ともに標準では動きません。GNOME などで Xorg セッションを選んでログインしてください。

## インストールと起動

```bash
cd remote-desktop

# 依存をインストール
python3 -m venv .venv
source .venv/bin/activate        # Windows は .venv\Scripts\activate
pip install -r requirements.txt

# 起動
python -m rdcontrol
```

`run.sh`(macOS / Linux)または `run.bat`(Windows)を使うと、仮想環境の作成から起動まで一度に行えます。

起動すると、接続用の URL がトークン付きで表示されます:

```
  接続 URL : http://127.0.0.1:8765/?token=Xk3n...   ← この URL をブラウザで開く
  トークン : Xk3n...
```

トークンは起動のたびにランダム生成されます(`--token` で固定も可能)。

### 別の端末から接続する

既定では `127.0.0.1` のみを待ち受けるため、同じ PC のブラウザからしか開けません。
**別の端末から使う場合は、SSH トンネル経由を推奨します**(通信が暗号化され、ポートを外に開かずに済みます):

```bash
# 操作したい側の端末で実行
ssh -N -L 8765:127.0.0.1:8765 ユーザー名@デスクトップのホスト
# その後、手元のブラウザで http://127.0.0.1:8765/?token=... を開く
```

信頼できる LAN 内でトンネルなしに使いたい場合のみ、待ち受けアドレスを広げます:

```bash
python -m rdcontrol --host 0.0.0.0
```

この場合、通信は暗号化されません(HTTP / WebSocket 平文)。
インターネットに直接公開しないでください。

## 主なオプション

| オプション | 説明 |
| --- | --- |
| `--host` | 待ち受けアドレス(既定 `127.0.0.1`) |
| `--port` | ポート(既定 `8765`) |
| `--token` | アクセストークンを固定する(既定は毎回ランダム) |
| `--monitor N` | 表示するモニタ番号。`0` は全モニタを結合した仮想画面 |
| `--fps N` | 最大フレームレート 1〜30(既定 10) |
| `--quality N` | JPEG 品質 10〜95(既定 60) |
| `--scale F` | 送信解像度の倍率 0.2〜1.0(既定 1.0)。回線が細いときに下げる |
| `--view-only` | 画面共有のみ。マウス・キーボード操作を一切受け付けない |
| `--max-clients N` | 同時接続数の上限(既定 4) |
| `--list-monitors` | モニタ一覧を表示して終了 |
| `--open` | 起動後にブラウザを自動で開く |

## ブラウザ画面の使い方

- **キーボード転送: OFF/ON** — ON にすると、押したキーが操作対象の PC に送られます。
  ブラウザ自身のショートカット(F5 / F11 / F12、および OS が予約する Alt+Tab など)は
  奪えないことがあるため、フッターのボタンから代表的な組み合わせを送れるようにしてあります。
- **画質 / FPS / 解像度** — 回線が細いときは解像度と FPS を下げると安定します。
- **モニタ** — 複数モニタがある場合に表示対象を切り替えます。
- **全画面** — 画面領域だけをフルスクリーン表示します。

操作できるのは同時に 1 人だけです。2 人目以降は「閲覧のみ」となり、
操作中のクライアントが切断すると次の接続者へ自動的に操作権が移ります。

## セキュリティについて

このアプリはデスクトップを丸ごと他の端末から操作可能にします。以下を前提に設計しています。

- **トークン必須** — ページと WebSocket の両方でトークンを検証します。比較は
  `secrets.compare_digest` によるタイミング攻撃耐性のある方法で行います。
- **既定はループバックのみ** — 明示的に `--host` を変えない限り、外部からは接続できません。
- **総当たり防御** — 接続元ごとに認証失敗を数え、既定 8 回で 5 分間ロックアウトします。
- **入力の検証** — クライアントから届く JSON は型・範囲・列挙値をすべて検証してからデバイス操作に渡します。
- **押しっぱなし防止** — 切断時やタブが非表示になったときに、押されたままのキー・ボタンを必ず解放します。
- **暗号化はしていません** — TLS は実装していないため、LAN 外で使うときは必ず SSH トンネル等で包んでください。

サーバーは Ctrl+C で停止できます。停止すれば外部からの操作経路は完全に閉じます。

## 通信プロトコル

WebSocket `/ws?token=...` の 1 本で双方向にやり取りします。

**サーバー → クライアント**

- バイナリフレーム: JPEG 画像そのもの
- `{"t":"hello", ...}`: 接続直後の初期情報(操作権の有無、モニタ一覧、初期設定)
- `{"t":"config", ...}`: 設定変更の反映結果
- `{"t":"pong"}` / `{"t":"error","message":"..."}`

**クライアント → サーバー**(座標はすべて 0.0〜1.0 に正規化)

| メッセージ | 内容 |
| --- | --- |
| `{"t":"mouse_move","x":,"y":}` | マウス移動 |
| `{"t":"mouse_down"/"mouse_up","x":,"y":,"button":"left"\|"right"\|"middle"}` | ボタン押下・解放 |
| `{"t":"scroll","x":,"y":,"dx":,"dy":}` | ホイール(ノッチ単位) |
| `{"t":"key_down"/"key_up","key":,"code":}` | キー操作(`KeyboardEvent` の値) |
| `{"t":"text","text":"..."}` | 文字列をまとめて入力 |
| `{"t":"config","quality":,"fps":,"scale":,"monitor":}` | 表示設定の変更 |
| `{"t":"ping"}` | 生存確認 |

座標を正規化して送るため、送信解像度を途中で変えてもサーバー側の座標計算は影響を受けません。

## 開発

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

テストは実画面・実デバイスに触れずに動くよう、キャプチャと入力を差し替え可能にしてあります
(`create_app(settings, capture=..., controller=...)`)。そのため CI やヘッドレス環境でも実行できます。

## 現時点の制限

- 音声の転送、クリップボード共有、ファイル転送は未対応です。
- Wayland セッションでは動作しません(X11 セッションを使ってください)。
- 動画のような激しい画面変化では、JPEG 全画面送信のため帯域を多く消費します
  (差分エンコードや WebRTC は未実装)。解像度と FPS を下げて調整してください。
- TLS 終端は行いません。LAN 外からは SSH トンネル等を経由してください。
